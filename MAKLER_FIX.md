# Инструкция по решению проблемы с HTTP 418 на makler.md

## Проблема
Сайт makler.md возвращает HTTP статус 418 ("I'm a teapot"), что является способом блокировки ботов.

## Решения

### 1. Тестирование различных заголовков
Запустите тест для проверки, какие заголовки работают:

```bash
node test-makler-headers.js
```

Этот скрипт проверит 4 разных набора заголовков и покажет, какой работает.

### 2. Тестирование с Puppeteer (рекомендуется)
Puppeteer имитирует реальный браузер и обходит большинство антибот защит:

```bash
node test-makler-puppeteer.js
```

Этот скрипт:
- Откроет реальный браузер (headless: false)
- Покажет процесс загрузки
- Сохранит скриншот и HTML если что-то пойдет не так
- Выведет первые 3 вакансии если все работает

### 3. Пересборка проекта
После внесения изменений в код:

```bash
npm run build
```

### 4. Запуск парсера
После успешного тестирования:

```bash
npm run parse makler.md
```

## Внесенные изменения

### В maklerMd.ts:
1. ✅ Улучшены заголовки HTTP запросов (добавлены Sec-Fetch-*, Cache-Control, DNT)
2. ✅ Добавлена retry логика (3 попытки с задержкой)
3. ✅ Добавлены случайные задержки между запросами (1-3 сек)
4. ✅ Увеличен timeout до 15 секунд
5. ✅ Добавлены Referer и Origin в запросы
6. ✅ Исправлено предупреждение TypeScript о неиспользуемой переменной

## Альтернативные решения

### Если HTTP запросы не работают:
1. Используйте Puppeteer парсер (создайте новый файл на основе rabotaMd.ts)
2. Добавьте proxy
3. Используйте rotating user agents
4. Добавьте cookies из реального браузера

### Создание Puppeteer парсера:
```typescript
// Замените fetchPage на:
private async fetchPageWithPuppeteer(url: string): Promise<string> {
  const browser = await puppeteer.launch({ headless: true });
  const page = await browser.newPage();
  
  await page.setUserAgent('Mozilla/5.0 ...');
  await page.goto(url, { waitUntil: 'networkidle2' });
  
  const html = await page.content();
  await browser.close();
  
  return html;
}
```

## Рекомендации

1. **Всегда используйте задержки** между запросами (минимум 1-2 секунды)
2. **Случайные задержки** делают поведение более человекоподобным
3. **Не делайте больше 10-20 запросов** за раз
4. **Используйте правильные заголовки** как в реальном браузере
5. **Puppeteer** - самое надежное решение для сложных сайтов

## Проверка результатов

После успешного парсинга проверьте:
- `vacancies_makler_md.json` - файл с вакансиями
- Количество найденных вакансий в выводе
- Нет ли дубликатов

## Если ничего не помогло

Возможно, сайт использует более сложную защиту:
1. Cloudflare Challenge
2. Captcha
3. JavaScript-based bot detection
4. Rate limiting по IP

В таких случаях рассмотрите:
- Использование Cloudflare bypass библиотек
- Proxy ротацию
- Captcha solving сервисы
- Selenium с расширениями против детекции
